# Milestone v0.1: Feature Improvements

**Status:** ✅ SHIPPED 2026-01-15
**Phases:** 5-7
**Total Plans:** 6 main + 3 fix plans

## Overview

Address critical bugs and add key features discovered during development - bidirectional pairing, improved pending state management, and UI polish for production readiness.

**Note:** v0.1 features shipped to internal/alpha/beta tracks while v0.2 (Play Store Launch) awaits production approval.

## Phases

### Phase 5: Bidirectional Pairing Architecture

**Goal**: Enable same phone number to exist in both "Forwarded to me" and "I forward to" sections simultaneously
**Depends on**: Phase 1 (basic app functionality must be stable)
**Status**: Complete
**Plans**: 1 main + 1 fix

Plans:
- [x] 05-01: Bidirectional Pairing Architecture Implementation
- [x] 05-01-FIX: UAT fixes for role-specific UNPAIR

**Key Changes:**
- Database schema: Composite primary key `(phoneNumber, device_role)` via MIGRATION_3_4

- Role-specific UNPAIR command: `SMSC UNPAIR SOURCE` / `SMSC UNPAIR TARGET`
- Updated 17 files including 5 test files

### Phase 6: Pending State & Pairing UX

**Goal**: Improve pairing workflow with resend capability, unpair acknowledgment, and abuse prevention
**Depends on**: Phase 5 (bidirectional architecture changes may affect this)
**Status**: Complete
**Plans**: 3/3 complete

Plans:
- [x] 06-01: Resend pairing request with rate limiting (database + ViewModel)
- [x] 06-02: UI for resend action (dropdown menu and visual feedback)
- [x] 06-03: Notification approve flow and smart UNPAIR

**Key Changes:**
- Database migration 4→5: Added resendAttemptCount and lastResendAttemptAt fields
- Rate limiting: Max 5 attempts, 1-minute cooldown between resends
- ResendStatus sealed class for exhaustive state handling
- Dropdown menu on long-press with contextual actions
- Visual feedback: Loading indicator replaces status badge during operations
- Snackbar confirmation pattern: StateFlow message + LaunchedEffect trigger
- Notification approve button deep-links to PairingRequestsScreen
- Smart UNPAIR: Only sends SMS for APPROVED devices (skips REJECTED, PENDING_*)

## Milestone Summary

**Key Decisions:**
- Composite primary key `(phoneNumber, role)` for bidirectional relationships (cleanest approach)
- Removed foreign key from ForwardingSession (Room doesn't support FK to composite PK)
- Rate limits: 5 attempts max, 1-minute cooldown (reasonable abuse prevention)
- Loading indicator replaces status badge (cleaner UX vs showing both)
- Notification approve navigates to UI rather than auto-approving (user sets password)

**Technical Debt Incurred:**
- ForwardingSession lacks foreign key (must handle orphaned sessions in app code)
- Database at version 5 (migrations must be maintained)

**Issues Resolved:**
- Bidirectional pairing now possible (same phone as SOURCE and TARGET)
- UNPAIR properly role-specific (deletes correct device)
- Pairing notification approve button now functional
- No unnecessary UNPAIR SMS for non-approved devices

**Stats:**
- 3 phases, 6 main plans, 3 fix plans
- Database migrations: 3→4→5
- ~30 files modified across phases
- All 228 unit tests passing
