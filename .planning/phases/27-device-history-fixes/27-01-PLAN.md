    ```kotlin
    /**
     * Archives a device locally without sending an UNPAIR SMS to the remote device.
     * - Ends any active session for the device (local only, no SMS).
     * - Archives the device so it appears in the Removed Devices section.
     * - The remote device is NOT notified; the pairing remains valid on their side.
     *
     * Use [unpairDevice] if you want to notify the other device.
     */
    fun archiveDevice(device: PairedDevice) {
        viewModelScope.launch {
            // End any active session locally (idempotent — no-op if none)
            sessionRepository.endSessionForDevice(device.phoneNumber, "ARCHIVE")

            // Archive the device with LOCAL initiator so ArchiveManagementScreen
            // shows "You initiated the removal" in the removal-reason copy.
            deviceRepository.archiveDevice(
                phoneNumber = device.phoneNumber,
                role = device.role,
                initiatedBy = "LOCAL",
            )
        }
    }
    ```

    Why `"LOCAL"` not `"USER"`: RESEARCH.md Open Question 3 — `ArchiveManagementViewModel.getRemovalReason()` distinguishes "LOCAL"/"REMOTE"/fallback. Passing "LOCAL" gives users the correct "You initiated the removal" message. The existing `unpairDevice()` passes "USER" which is a latent bug but is OUT OF SCOPE for Phase 27 (documented as follow-up in RESEARCH).

    Why `"ARCHIVE"` stoppedBy: Distinguishes archive-initiated session termination from UNPAIR in historical records.

    Do NOT:

    - Touch `unpairDevice` or any other method
