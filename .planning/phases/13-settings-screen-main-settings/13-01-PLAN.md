# 13-01: Settings Screen Navigation and Layout

## Objective

Create the settings screen foundation with proper navigation, ViewModel pattern, and theme observation at the app level. This establishes the scaffold that Plans 13-02 and 13-03 will populate with actual settings.

Purpose: Enables user access to settings and ensures theme changes apply immediately app-wide.
Output: SettingsScreen.kt, SettingsViewModel.kt, updated NavGraph.kt and MainActivity.kt

**Key patterns from codebase:**
- LargeTopAppBar with back navigation icon (HomeScreen.kt pattern)
- ViewModel with Factory pattern (HomeViewModel.kt)
- SettingsRepository instantiation: `remember { SettingsRepository(context) }`
- Theme composable: `smscourierTheme(darkTheme = ...)` in MainActivity.kt

**From Phase 12:**
- SettingsRepository.theme returns `Flow<AppTheme>`
- AppTheme enum: LIGHT, DARK, SYSTEM
- Default is SYSTEM

**MainActivity.kt changes:**

1. Add imports:
   - `import androidx.compose.foundation.isSystemInDarkTheme`
   - `import androidx.compose.runtime.collectAsState`
   - `import androidx.compose.runtime.getValue`
   - `import dev.notyouraverage.smscourier.data.settings.AppTheme`
   - `import dev.notyouraverage.smscourier.repository.SettingsRepository`

2. Inside setContent block, BEFORE smscourierTheme call:
   ```kotlin
   val settingsRepository = remember { SettingsRepository(applicationContext) }
   val themeSetting by settingsRepository.theme.collectAsState(initial = AppTheme.SYSTEM)

   val darkTheme = when (themeSetting) {
       AppTheme.LIGHT -> false
       AppTheme.DARK -> true
       AppTheme.SYSTEM -> isSystemInDarkTheme()
   }
   ```

3. Update smscourierTheme call to pass darkTheme:
   ```kotlin
   smscourierTheme(darkTheme = darkTheme) {
       // ... existing content
   }
   ```

Note: This creates two SettingsRepository instances (MainActivity and NavGraph). This is acceptable because DataStore is a singleton at the Context level - both instances share the same underlying DataStore. Alternative approaches (dependency injection, CompositionLocal) add complexity without benefit for this use case.
