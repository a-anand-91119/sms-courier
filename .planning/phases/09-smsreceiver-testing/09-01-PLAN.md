Add command routing tests verifying correct Intent extras sent to MasterService:

1. `routes PAIR_REQUEST command to MasterService` - "SMSC PAIR_REQUEST"
2. `routes PAIR_APPROVED command to MasterService` - "SMSC PAIR_APPROVED"
3. `routes PAIR_REJECTED command to MasterService` - "SMSC PAIR_REJECTED"
4. `routes UNPAIR command to MasterService` - "SMSC UNPAIR"
5. `routes UNPAIR with role to MasterService` - "SMSC UNPAIR SOURCE"
6. `routes AUTH_REQUEST command to MasterService` - "SMSC AUTH_REQUEST"
7. `routes AUTH_CHALLENGE command with nonce` - "SMSC AUTH_CHALLENGE abc123"
8. `routes START_FORWARD command with password` - "SMSC START_FORWARD secret123"
9. `routes START_FORWARD with duration` - "SMSC START_FORWARD secret123 60"
10. `routes STOP_FORWARD command to MasterService` - "SMSC STOP_FORWARD"
11. `routes FWD command with original sender and message` - "SMSC FWD +1234567890 Hello"
12. `routes FWDE encrypted command` - "SMSC FWDE +1234567890 encryptedBase64"
13. `ignores unknown SMSC command` - "SMSC UNKNOWN_COMMAND"
14. `does not route non-SMSC messages` - "Regular SMS message"

For each routing test, verify:
- Service intent action is MasterService.PROCESS_COMMAND
- EXTRA_SENDER contains sender phone number
- EXTRA_COMMAND_TYPE matches expected type
- Command-specific extras (EXTRA_NONCE, EXTRA_PASSWORD, EXTRA_DURATION, etc.)

If PDU construction proves too complex, document the limitation and test handleCommand via reflection or by making it package-private for testing.
